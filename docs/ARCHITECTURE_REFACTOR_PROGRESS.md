## Executive Summary

The Todorbit Architecture Improvement Program (Milestones ARCH-03 through ARCH-09) systematically resolves structural coupling, presentation rebuild cascades, fragile orchestration typing, and database transaction leakage across the desktop and mobile codebases. All improvements adhere to the non-negotiable invariants of offline-first zero data loss, CAS concurrency tokens, SQLite atomicity, and Google Drive sync protocol stability.

## Before & After Architectural Comparison

| Architectural Dimension | Before Refactoring (Baseline `dc164ae`) | After Refactoring (Milestones ARCH-03 – ARCH-09) | Architectural Benefit |
|:---|:---|:---|:---|
| **Component Coupling (`SyncStatusButton`)** | `SyncStatusButton` directly imported `settings/sync_settings_page.dart` and `sync_conflicts_dialog.dart`, creating a circular dependency from `features/shared/` to `features/settings/`. Hardcoded debug `assert(false)` caused test crashes when callbacks were omitted. | `SyncStatusButton` relies strictly on optional typed callbacks (`SyncOpenSettingsCallback`, `SyncOpenConflictsCallback`). Missing callbacks trigger graceful, non-crashing SnackBar notices with mounted context checks. | Reusable shared components have zero inward dependencies on high-level feature screens. |
| **Feature Boundary Cycles (`calendar` vs `workspace`)** | Bidirectional cyclic imports between `lib/features/calendar/` and `lib/features/workspace/`: `event_editor.dart` imported `workspace/task_editor.dart`; `workspace/task_editor.dart` imported `calendar/session_editor.dart`. | `session_editor.dart` extracted to `lib/features/scheduling/` (with compatibility re-export). Shared navigation contracts (`EditorNavigationController`) extracted to `lib/features/shared/unsaved_editor_guard.dart`. `event_editor.dart` imports shared controller directly. | Clean unidirectional feature dependency graph. Verified and continuously ratcheted by `tools/test_architecture_boundaries.py`. |
| **Orchestration Refresh Typing (`AppController.refresh`)** | Loaded 29 queries concurrently via `Future.wait<Object?>([ ... ])` and unpacked results using fragile, magic integer indices (`results[0] as List<AlarmRule>`, `results[1] as List<Category>`, ..., `results[28] as List<LifeTask>`). Swapping or inserting a query silently corrupted runtime state assignments. | Encapsulated in `AppRefreshSnapshot.load(...)` returning strongly typed, named fields. State assignments in `_applyRefreshSnapshot` map typed fields directly to controller state. | 100% type safety on concurrent multi-query refresh. Result mapping fully verified by dedicated test suite `app_controller_refresh_mapping_test.dart`. |
| **State Exposure & Mutability** | `AppController` exposed 25+ public collection fields as raw mutable `List` and `Map` instances (`List<LifeTask> get tasks => _tasks;`, `List<Habit> habits = [];`, etc.). Any external consumer could call `.add()`, `.clear()`, or `.sort()`, bypassing change notifications and cache invalidation. | All public collection getters expose `UnmodifiableListView` or `UnmodifiableMapView`. Internal mutations happen exclusively through controlled controller methods. | Immutable state encapsulation; external mutations cannot silently corrupt in-memory state. |
| **Rebuild Cascades & Rendering Performance** | `_LifeManagerState` in `lib/main.dart` watched `appControllerProvider` directly without selectors (`ref.watch(appControllerProvider)`). Every `notifyListeners()` call in the app triggered a full rebuild of the root `MaterialApp`. `WorkspaceState` ran an active 1-second timer calling `setState(() {})`, rebuilding 2,600+ lines of desktop UI every second. | `lib/main.dart` uses scoped Riverpod selectors (`ref.watch(appControllerProvider.select((c) => c.theme))`, etc.). The 1-second active timer clock is isolated inside `CompactTaskTimerBadge`, allowing the badge to tick locally without triggering parent `Workspace` rebuilds. | Vastly reduced frame rendering overhead and eliminated unnecessary UI redraw cascades across desktop and mobile. |
| **Database Transaction & Lifecycle Encapsulation** | `LifeRepository` exposed `public final AppDatabase db;`. `AppController` opened raw SQLite transactions (`repository.db.transaction`) to orchestrate multi-entity mutations across tasks, subtasks, checklists, and goals. `software_updates_page.dart` directly invoked `repository.db.close()`. | Multi-record mutations are encapsulated behind composite repository methods (`addSubtaskWithComposition`, `addTaskWithComposition`, `addRecurringTaskWithComposition`, `addGoalWithComposition`). Database closing is encapsulated behind `LifeRepository.close()` and `AppController.closeDatabase()`. `LifeRepository.db` is marked `@visibleForTesting`. | Prevents leakage of SQLite transactions into presentation/orchestration layers while strictly preserving WAL atomicity, CAS tokens, and `sync_mutation_groups`. Enforced by CI boundary tests. |
| **Feature Modularity & Extensibility** | Unstructured architecture where disabling a built-in feature was undefined or risked dropping tables and corrupting `portableSyncTables` across devices. | Evaluated and codified preference-driven modular monolith architecture (`docs/OPTIONAL_FEATURE_MODULARITY_EVALUATION.md`). Modular navigation visibility is safely managed via `hiddenNavigation` preferences without destructive SQLite migrations or cloud sync protocol risks. | Predictable modular monolith with zero risk of sync desynchronization or data loss. |
| **Architecture Boundary Tooling & Enforcement** | `tools/test_architecture_boundaries.py` only checked calendar presentation contracts and calendar child-to-root boundaries. Direct database leakage and domain layer impurities were unchecked. `tools/dev/features.json` was missing 8 core features. | `tools/test_architecture_boundaries.py` now enforces: (1) Calendar/Workspace bidirectional isolation, (2) Shared/Settings decoupling, (3) Platform dialog isolation, (4) Direct raw database handle prohibition (`.db.transaction`, `.db.close`) in app and features, and (5) Domain layer purity (no Flutter/app/data imports in `lib/domain/`). `tools/dev/features.json` contains all 19 features with verified test paths. | Automated CI gate prevents architectural drift, circular dependencies, and database leakage. |

   - **Android 16 KiB Page Size Alignment & Physical Device Testing**: Executing `tools/test-android-update.ps1` against an isolated emulator or physical device to verify APK alignment, Android 16 KiB memory page compatibility, and native touch widget lifecycle.
   - **Production Google Drive OAuth & Remote Sync**: Interactive verification using isolated test Google accounts to confirm end-to-end cloud snapshot backup and incremental sync recovery without synthetic mocks.
